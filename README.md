# rufusforlinux-web

## Description

This is the content repository for the Rufus for Linux homepage, the
documentation site of [Rufus for Linux](https://github.com/0peratorXXX/rufusforlinux)
&mdash; the native Linux port of [Rufus](https://rufus.ie) for creating
bootable USB drives and disk images.

Because GitHub **does not care** about multilingual support when hosting web
pages using their recommended tools, we have to manually generate our own
localized pages from PHP content and gettext.

The way it works is as follows:
1. `index.php` is edited to reflect the latest updates we want visitors to see.
2. This PHP content is uploaded to an Apache+PHP+gettext server, along with the
   localization files.
3. This server is then queried through a bash script `_refresh.sh` to generate
   the static content (the various `index.html` in the subdirectories), which is
   then deployed to GitHub, as static pages, and served from GitHub Pages.

The root `index.html` is also generated by `_refresh.sh`: it is a small
JavaScript redirector that sends visitors to the subdirectory matching their
browser language, falling back to `en`.

## Updating the content

```bash
# 1. Edit index.php, then extract the translatable strings
./_create_pot.sh

# 2. Merge the new msgids into every existing catalog and recompile them
cd locale
for po in $(find . -name "index.po"); do
  msgmerge --quiet --update --backup=none "$po" ./index.pot
  msgfmt -o "${po%.po}.mo" "$po"
done
cd ..
```

New strings ship untranslated, so a localized page falls back to the English
copy for anything the catalog does not cover yet.

## Deploying and testing your own local site

While we use a real local Linux server for our internal PHP deployments, if you
have Docker installed (and can use Docker commandline), you should be able to
replicate our intermediate PHP server by issuing the following Docker commands:

```
cd <directory where you cloned this repo>
docker build -t rufusforlinux-web .
docker run -p 8080:80 rufusforlinux-web
```

Then, by accessing http://localhost:8080 you should see the original localized
website. Note that images will *not* render in this preview: `index.php` emits
asset paths that are relative to the locale subdirectory (`../pics/...`), which
is how the pages are served from the `gh-pages` branch under
`https://<user>.github.io/<repo>/<locale>/`. This server exists only to render
the static pages that `_refresh.sh` then writes; it is not a supported way to
host the site.

If you have a `bash` compatible shell installed, you should also be able to
generate the static localized pages, by issuing the following commands:

```
php -S localhost:8080 &          # serve index.php locally
./_refresh.sh                   # writes <locale>/index.html and index.html
```

`_refresh.sh` expects the server at `url=localhost:8080`; change the `url`
variable at the top of the script if yours listens elsewhere.
